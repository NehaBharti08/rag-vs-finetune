environment before the project started:

|---|---|
| `bitsandbytes 0.50.0` | requires `transformers<5` |

| Base env on this machine | `transformers 5.14.1` on Python 3.13 — **outside the window** |

That is why this project uses its own `uv` venv pinned to Python 3.11.

## Compute budget: projected vs actual

The original projection is kept below the line because the gap between it and
reality is the more useful number.

### What actually happened

| Item | Projected | **Actual** |
|---|---|---|
| Training examples | 4,000 | **2,830** |
| Mean tokens/example | 600 (estimated) | **137** (measured, Phase 1) |
| `max_seq_length` | 2048 | **512** |
| Packing | on | **off** (deliberate — see `ragft.train.sft`) |
| One 3-epoch run | 3.17 GPU-h | **0.743 GPU-h** |
| Peak reserved | 11.88 GiB | **10.91 GiB** |

The projection was **4.3× too high**, for one reason worth keeping: a training
example here is a question plus a formatted answer and contains **no passage**,
because the no-retrieval arm has to recall parametrically. There was never a
long context to hold. Padding to 2048 would have wasted ~11× the compute for
nothing.

Packing was then turned **off**, which is the opposite of a compute
optimisation and was chosen anyway: on this dataset the binding constraint is
signal, not compute. Packed gives ~95 optimizer steps/epoch, unpacked ~353 —
same data, roughly the same wall clock, 3.7× more gradient updates.

Headroom held up. The measured 10.91 GiB peak on a 22.05 GiB card is what kept
runs alive on a shared GPU, which mattered more than speed throughout.

### Recalibrated compute budget

Projected from measured throughput, assuming 4,000
training examples averaging **600 tokens each**.

⚠️ The average example length — not `seq_len` — drives this. With packing on,
short examples are concatenated to fill each 2048-token block, so
4,000 examples of ~600
tokens occupy roughly 1,171 sequences, not
4,000 of them. Using `examples x seq_len` instead
overstates the budget by the packing ratio (~3.4x here).

The token count itself is still an **estimate** until Phase 1 measures the real
length distribution of (passage + question + formatted answer). Throughput is
measured; the example length is not, yet.
